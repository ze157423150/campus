## 如何解释

立即投递减少等待定时扫描的时间，定时任务继续作为补投保障。200 用户各请求 5 次的场景，整批完成时间从约 39 秒降至约 1.56 秒；这不表示所有请求的延迟均下降相同比例，也不代表 1000 个不同用户都被成功受理。

整批完成包含数据库终态与 pending 清空的等待，检测采用轮询；不是单个订单的 P95。HTTP P95 包括失败与重复请求，原始 JSON 中 acceptedHttpP95Ms 才是受理请求的对应指标。

客户端与服务端在同一 JVM，短时批量请求算出的 requests/second 不代表持续吞吐或独立压测机下的容量。预热场景的 HTTP P95 反而较高，不能声称每项指标都提升。没有在本次文档整理中重现这些历史结果。
